# Stasy Bell OS — MVP 1.0

Дата фиксации требований: 2026-11-02. Статус: утверждённое продуктовое направление, реализация не начата.

## Цель

Собственная система для одного мастера: онлайн-запись клиентов через существующий React-сайт, ручное создание записей мастером, простой учёт доходов/расходов и **нативное Android-приложение только для мастера**. DIKIDI не используется в целевой архитектуре.

## Каналы и права

- Клиенты: только сайт, затем связь через Telegram или ВКонтакте; никаких клиентских Android-приложений и обязательной регистрации.
- Мастер: Android на Kotlin + Jetpack Compose, авторизация, календарь, клиенты, деньги, расходы, расходники, уведомления.
- Сервер: единый API + PostgreSQL; размещение и хранение персональных данных граждан РФ с учётом требований законодательства; конкретный хостинг пока не выбран.
- **Бесплатные уведомления:** Telegram Bot API и сообщения сообщества VK в рамках разрешений API. Платные SMS пока исключены.
- Telegram-бот не может писать пользователю до первого /start. Использовать deep link со случайным одноразовым идентификатором заявки, а не с персональными данными.
- Автоматические сообщения VK предполагают общение от имени сообщества, у которого включены сообщения и получено согласие пользователя, не от личного аккаунта мастера.
- Ручные записи, созданные после звонка / личных сообщений, не требуют бот-подтверждения; мастер сам отмечает их как подтверждённые.
- Предпочтительный канал связи хранится в карточке клиента вместе с фактически привязанным ID чата/пользователя, если такой ID получен легитимным образом. Одного телефона недостаточно для автоматического начала переписки.

## Онлайн-запись: состояние и правила

Клиент выбирает услугу, подходящий старт и контакт. Сервер временно резервирует **весь интервал услуги**. Клиент выбирает Telegram/VK и подтверждает намерение в указанном канале.

- Время удержания слота: **45 минут** от создания заявки.
- Время жизни одного одноразового токена подтверждения: **15 минут**; повторная выдача возможна в пределах оставшегося 45-минутного окна, с rate-limit.
- Варианты статуса: `pending_channel`, `confirmed`, `expired`, `cancelled`, `completed`, `no_show`.
- При подтверждении: атомарно установить `confirmed`, записать в единый календарь, создать уведомление мастеру и ответ в выбранном канале; повторный callback не создаёт дубль.
- Если подтверждение не произошло за 45 минут: освободить слот, `expired`, запретить подтверждать старый токен.
- Слоты рассчитываются по рабочим дням мастера, длительности и буферам выбранной услуги, блокировкам/отпускам, уже созданным записям. Диапазон доступных дат — ближайшие 30 дней.
- Длительности и перерывы **редактируются мастером**, первоначальные значения требуют согласования; не зашивать средние 5 часов для всех услуг.
- Проверять пересечения на уровне транзакции БД, а не только интерфейса. Блокировки/бронь/ручные записи участвуют в одной проверке; временные зоны `Europe/Moscow` (Санкт-Петербург, UTC+3).
- Блокировать спам: лимиты на запросы/бронь, защита от перебора токенов, проверка webhook, журнал событий.
- При отсутствии согласия/первого контакта в канале предлагать понятный ручной сценарий, не утверждать, что бот отправил сообщение.

## Запись мастером с Android

Мастер может создать запись после звонка, личного сообщения либо прямо в кабинете:
1. Нажать «+ Запись», выбрать существующего клиента либо создать новую карточку.
2. Выбрать услугу/комбинацию услуг, дату, старт, расчетную длительность и ориентировочную цену (редактируемые поля).
3. Проверка пересечений в едином календаре, ручная отметка `confirmed`.
4. Опционально открыть Telegram/VK контакт клиента или отправить уведомление только когда канал действительно подключён.
5. Переносить, отменять, завершать и отмечать неявку; история изменений сохраняется.

Поле `source`: `website`, `phone`, `telegram_manual`, `vk_manual`, `other_manual`.

## Финансы — простой режим для одного мастера

- Текущий месяц: живой журнал **фактических** доходов и расходов. Доход отражается по завершённой/оплаченной процедуре (или отдельным поступлением), бронь сама по себе не является выручкой.
- Расходы: материалы, аренда, налоги, реклама, прочее. Не вводить сложную бухгалтерию, план-факт и прогнозные обязательства в MVP.
- После закрытия месяца: зафиксировать сводный снимок доходов, расходов и простую разницу; исправления с аудитом, без скрытой перезаписи.
- Услуги, покупка составов и их остатки сначала учитываются в минимальном виде; точную поуслуговую себестоимость можно добавить после накопления данных.
- Денежная выручка и расчётная прибыль никогда не должны смешиваться без явных пометок.
- На Android показать текущие поступления, расходы, разницу, количество клиентов и будущие записи.

## Перенос исторических Excel

Входные источники: `stasy_bell_database.xlsx`, `Stasy Bel - кератин, ботокс.xlsx`.

- Оригинальные файлы и клиентские сведения **не сохранять в публичном GitHub**; перенос только через защищённую миграцию на сервер.
- Сначала создать staging-таблицы и проверить дубли по телефону/имени/датам. Конфликтные связи — только на ручную верификацию; сохранять provenance.
- Отличать старые расчёты `оценка прибыли` от новых фактических операций. Закрытые исторические месяцы не пересчитывать автоматически.
- Зафиксировать количество считанных/объединённых/отложенных записей и суммы до/после импорта. Нужен dry-run и отчёт о расхождениях.

## Приоритеты внедрения и критерии приемки

1. **Адрес:** Санкт-Петербург, ул. Ольги Берггольц, 9, корп. 2 — первый экран, контакты, карта, SEO/schema.org, оферта.
2. **Основа:** отдельное API, схема БД, аутентификация мастера, инфраструктура/бэкапы, тесты и безопасный конфиг.
3. **Календарь:** открытые окна на 30 дней, длительности услуг, ручная запись, защита от пересечений. Две одновременные заявки не получают один интервал.
4. **Подтверждение:** Telegram deep-link, VK-сообщество, hold=45 минут/token=15 минут, повторные callback безопасны, истечение освобождает слот.
5. **Клиенты и деньги:** журнал операций, расходы, завершение визитов, месячные итоги, импорт истории с очисткой.
6. **Android:** Kotlin/Compose, календарь/клиенты/финансы, уведомления, безопасное хранение токенов, тестовый подписанный APK.
7. **Сайт:** подключить бронирование к API, заменить старую неработающую отправку в Google Apps Script, убрать DIKIDI и обновить UX/SEO.

## Не включать в MVP

Платные SMS, клиентские приложения, прогноз обязательств, сложную финансовую модель, каталог продуктов на продажу, интеграции со всеми мессенджерами, публикацию Android-приложения в магазине.

## Технические ограничения / зависимости

- Доступ к реально действующему VK-сообществу и создание Telegram-бота необходимы для полного запуска.
- Секреты ботов, базы и Android-подписи хранятся только в секрет-хранилище/переменных окружения, **не в репозитории**.
- Развёртывание приложения/сервера и импорт реальных клиентских данных отдельно от публикации статического GitHub Pages.
