# Подключение Telegram/VK — всё готово к получению секретов

Это **закрытый код**, работа с реальными ботами пока не включена. Основной GitHub Pages не меняется.

1. **Telegram:** прислать приватно/ввести на сервере `TELEGRAM_BOT_TOKEN` и имя бота `TELEGRAM_BOT_USERNAME`. Сгенерировать отдельно `TELEGRAM_WEBHOOK_SECRET` и указать `TELEGRAM_OWNER_CHAT_ID` Насти. Настя должна первой написать боту, иначе Telegram запрещает боту писать ей.
2. **VK:** создать сообщество/включить сообщения и Callback API. На сервер ввести `VK_GROUP_ID`, `VK_GROUP_ACCESS_TOKEN`, `VK_CALLBACK_SECRET`, `VK_CONFIRMATION_CODE`, `VK_COMMUNITY_SCREEN_NAME`. Не использовать личный токен VK.
3. После подготовки HTTPS адреса зарегистрировать Telegram webhook `/callbacks/telegram` с секретным заголовком, выбрать `message` и `callback_query`. В настройках сообщества VK указать `/callbacks/vk`, подтвердить адрес и включить событие `message_new`. URL требует реального публичного TLS хоста. На старте `STASY_PUBLIC_BOOKING_ENABLED=0`.
4. Проверить в тестовой среде (не с настоящими клиентами): заявка → временная бронь 45 минут → код 15 минут → подтверждение через Telegram-кнопку / сообщение сообщества VK → статус на сайте confirmed → появление одной записи в календаре → уведомление Насте в Telegram.
5. После приёмки включить `STASY_PUBLIC_BOOKING_ENABLED=1` и точный HTTPS-origin сайта. До этого сайт предлагает ручной контакт.

Все ключи перечислены в `v2/.env.messengers.example` без значений. **Одного токена недостаточно для запуска**: нужен публичный HTTPS-адрес, регистрация webhook и проверка безопасности.

## Уведомления

При подтверждении сайт не создаёт вторую запись: событие и элемент `owner_notifications` записываются в одной транзакции. Необязательный `worker` профиль Docker Compose отправляет сообщение Насте через Telegram, повторяя сбои с увеличивающейся паузой до 12 попыток. База не теряет уведомление при перезапуске worker. Доставка at-least-once, после аварии между доставкой и DB-фиксацией возможно повторное уведомление. Без credentials отправка не производится. Никаких токенов и реквизитов в репозитории нет.

В браузере публичный статус доступен только с отдельным секретом удержания через POST (без PII). Сайт перепроверяет статус каждые 15 секунд и никогда не обозначает неподтверждённую бронь как подтверждённую.

Проверки с реальными ботами и в эмуляторе пока не проведены.
