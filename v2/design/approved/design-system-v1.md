# Stasy Bell — единая дизайн-система сайта и Android-приложения

**Дата фиксации:** 03-11-2026  
**Режим:** один бренд, две самостоятельные темы; единые UX-правила и токены компонентов.  
**Решение:** сайт — **светлый sage / editorial premium**; приложение — **глубокий зелёный / modern eco / restrained glass**.

> **Назначение файла.** Это рабочая спецификация для дизайна и реализации в Codex. Она накладывает утверждённые палитры Stasy Bell на структуру исходного `DESIGN-nerdwallet.md`. От исходника сохраняем прагматичную иерархию, плотность информации, сетку, тонкие разделители, минимум теней, честные состояния компонентов. Не копируем цвета, фирменные элементы, рекламные компоненты или финансовую терминологию NerdWallet.
>
> **Происхождение HEX.** Цвета ниже — зафиксированные токены интерпретации согласованных визуальных референсов, **не результат инструментального измерения пикселей**. В дальнейшем менять их можно только централизованно, после визуальной приёмки обоих продуктов.

## 1. Архитектура бренда: что общее, что различается

| Правило | Публичный сайт — `sage-editorial-light` | Android — `forest-glass-operational` |
|---|---|---|
| Задача | Доверие, услуги, портфолио, запись онлайн | Быстрая работа мастера, календарь, клиенты, деньги, остатки |
| Характер | Журнальная эстетика, лёгкий премиум, натуральные оттенки | Зелёный уверенный акцент, спокойные рабочие поверхности |
| Цветовой баланс | 75% светлые нейтрали / 20% sage-mint / 5% акценты | 65% светлые поверхности / 25% глубокий зелёный / 10% состояния и акценты |
| Типографика | Контрастная editorial serif для крупных заголовков + чистый sans для UI | Только читабельный sans для рабочих экранов; брендовый serif допускается в логотипе |
| Стекло / 3D | Очень деликатно: hero, плавающая форма записи, промо | Умеренно: шапка главной, KPI, всплывающие панели; **не** таблицы и длинные списки |
| Приоритет | Эмоция → доверие → запись | Информация → действие → подтверждённый результат |

**Общее ДНК:** простые сетки, 8-пиксельный ритм, чёткая типографическая иерархия, тонкие `hairline`-разделители, тактильные, но некричащие интерактивные элементы, иконки 18–20 px/dp без избыточной декоративности. Цвет — навигационный инструмент, а не фон ради фона.

### 2.3. Единые семантические цвета

| Событие | Цвет | Правило |
|---|---|---|
| Успех / завершено / положительная динамика | `#1F6342` | Обязательно подтверждать словом или пиктограммой |
| Предупреждение / остаток снижается | `#996017` | На светлом фоне; статус — не только цветом |
| Ошибка / удалить / отменить с последствиями | `#B3261E` | Выделять только действительно опасные действия |
| Информация / дополнительная справка | `#3C708B` | Второстепенный смысл, не конкурирует с зелёной кнопкой |
| Неактивно | `muted` + сниженная насыщенность | Читаемые подписи и объяснение причины |

**Контраст:** белый текст на `web.primary` ≈ **5.8:1**, на `app.primary` ≈ **7.2:1**, на `app.primary-deep` ≈ **13:1**. Это расчёт для **непрозрачной заливки**; на полупрозрачных слоях контраст проверять заново. Целевой WCAG AA: минимум 4.5:1 для обычного текста и 3:1 для крупного текста и значимых элементов. Пастельные `sage`/`gold-micro` **не использовать** как основной текст на белом.

## 3. Типографика — иерархия из исходных правил

Основа из `DESIGN-nerdwallet.md`: вес и контраст важнее бесконечного увеличения кегля. Базовая семья исходника — `Gotham / GothamDisplay` (лицензионная); **без легальной лицензии не включать файлы шрифтов в проект**. Для реализации использовать **Inter** (интерфейс, Android) и, только для крупных editorial-заголовков сайта, **Playfair Display**. Другие допустимые sans-замены по исходнику: `Montserrat`, `Jost`.

| `display-lg` | 40/48, 600, Playfair | — | Крупный editorial-заголовок |

## 4. Сетка, формы, глубина

### 4.1. Spacing — сохраняем оригинальную 8-pt систему

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40` px (web) и dp (Android). Отступы до и после крупных групп больше, чем внутри строк. Цифры, подписи и действия всегда визуально выровнены. Не раздувать одну карточку на половину экрана ради единственного числа.

### 4.2. Радиусы — адаптация правил под утверждённые референсы

| Элемент | Сайт | Android |
|---|---:|---:|
| Поля и небольшие controls | 6–8 px | 8–10 dp |
| Строки списков | 8–10 px | 10–12 dp |
| Основные карточки | 12 px | 12–16 dp |
| Модальные окна / glass-панели | 16 px | 16–20 dp |
| Пилюли фильтров / чипы | 9999 px | 9999 dp |

Исходные квадратные кнопки NerdWallet (`2px`) здесь **осознанно переопределяются**: они не соответствуют утверждённым изображениям Stasy Bell. При этом сохраняем компактность и строгие формы.

### 4.3. Глубина и стекло

- **Level 0** — фон и таблицы, без теней.
- **Level 1** — разделитель `1px/dp`, цвет `border`.
- **Level 2** — карточка: тонкая граница + слабая тень (`0 4px 16px rgba(20,45,30,.04)`).
- **Level 3** — акцентная KPI/фильтр/фиксированная панель: тень до 6–8% + лёгкий градиент.
- **Level 4** — диалог, bottom sheet, floating action: мягкая тень, чёткий непрозрачный контентный слой.

**Glass rule:** полупрозрачность, фоновые размытия и подсветка допустимы **только** в декоративных и ненагруженных областях: верхняя hero-панель, компактные KPI, floating toolbar, bottom sheet. Для расписаний, сумм, таблиц клиентов и длинных форм — **непрозрачные белые карточки**. Если стекло ухудшает читаемость — отключить его, не снижать размер шрифта.

**3D:** ботанические листовые формы, тонкая глубина и световой изгиб в брендинге. Ни анимированных тяжёлых эффектов, ни декоративных объектов поверх управления. В Android анимация 160–220 мс для смены состояний; учитывать системный `reduce motion`.

## 5. Компоненты и состояния

| Компонент | Геометрия / контент | Состояния и поведение |
|---|---|---|
| `button-primary` | Заливка `primary`, белый текст, компактный радиус, min-height 44 px / 48 dp | default, pressed, loading, disabled; на Android одна главная CTA на экран |
| `button-secondary` | Белая или `canvas-soft` поверхность, тёмный текст, тонкая рамка | Явно слабее primary |
| `button-outline` | Прозрачный фон, граница `border`, тёмный текст | Для вспомогательного действия; hit area не меньше стандарта |
| `text-input` | Светлое непрозрачное поле; label **над** значением | default, focus, error с текстом, disabled, read-only |
| `app-card` / `service-card` | Небольшой радиус, 1px/dp граница, чёткие строки | Информация на карточке читается без открытия |
| `stat-block` | Подпись над крупным числом, единица ₽ / шт / мл / г | Число + период + тип показателя; не путать выручку и факт. поступления |
| `status-chip` | Контрастный короткий label + пиктограмма при необходимости | `Ожидает`, `Подтверждена`, `Отменена`, `Завершена` — значение не кодировать одним цветом |
| `filter-chip` | Компактный pill с активной заливкой | 1 активное состояние на фильтр; горизонтальная прокрутка без переноса в 3 ряда |
| `list-row` | 1–2 строки + trailing action, тонкий `hairline` | Swipe только как дополнение, основные действия доступны явно |
| `bottom-nav` | 5 пунктов, 18–20dp иконки + подписи | Главная / Календарь / Клиенты / Финансы / Ещё; не скрывать подписи |
| `floating-add` | Один плюс на нужных операционных экранах | Размер зоны нажатия ≥48dp; не закрывает нижнюю запись |
| `date-picker` | Предпочтительно native/Compose + брендовые акценты | Недоступные даты/время объяснять; timezone Europe/Moscow для отображения студии |
| `dialog` / `bottom-sheet` | Непрозрачный основной контент + умеренный glass фон | Деструктивные действия подтверждаются, ошибки остаются читаемыми |
| `empty-state` | Краткое объяснение + одно полезное действие | Без огромных иллюстраций и пустого экрана |
| `chart` | Чистые оси, 1–2 графических серии, доступные текстовые значения | Всегда указаны период, ₽ / число записей, источники данных и смысл показателя |

**Размер иконок:** 18–20 px/dp в меню и списках, 22–24 dp допускается для ключевого действия. Никаких «плиток» с иконкой 48–64 dp ради красоты. Касательная область нажатия при этом остаётся **не менее 44×44 px веб и 48×48 dp Android**.

## 6. Карта экранов — сайт

| Экран / секция | Иерархия и цвет | Обязательное содержимое |
|---|---|---|
| Главная / hero | Светлый editorial, реальная фотография волос, serif-заголовок, зелёная CTA | Краткое позиционирование, «Записаться», «Услуги», маршрут к записи |

| Онлайн-запись | Белая практичная форма, зелёная активная дата/слот | Выбор услуги, свободные окна из API, контакты, статус подтверждения через мессенджер |
| Работы / портфолио | Приоритет фотографий над декоративными эффектами | Реальные фотографии и категории; разрешение на публикацию |
| О студии / мастер | Текст, светлые блоки, детали studio-brand | Данные студии и мастера, актуальные контакты |
| Контакты | Простая светлая карта/схема + текст | Санкт-Петербург, ул. Ольги Берггольц, 9, корп. 2; способ связи |
| Подтверждение / ожидание | Сдержанные статусы на белой панели | Явное «ожидает», «подтверждена» или ошибка, дальнейший шаг |

**Не обещать запись там, где интеграция ещё не включена.** При отключённом публичном бронировании предусмотрено безопасное и ясное состояние. Никакого фальшивого «Подтверждено» только потому, что красивая анимация закончилась.

## 7. Карта экранов — Android Stasy Bell OS 2.0

| Экран | Структура и действия | Дизайн-принцип |
|---|---|---|

| 07. Клиенты — список | Поиск, фильтры, имя/телефон/последний визит | Строки с тонким разделителем, быстрый поиск |
| 08. Карточка клиента | Контакты, история визитов, записи, заметки, суммы по доступным данным | Акцент на истории, не на огромной аватарке |
| 09. Услуги | Категории, цена, длительность, редактирование, создание | Плотные карточки; при редактировании сохранять все существующие поля |
| 10. Финансы — обзор | Выбранный период, факт. доход/расход/разница, динамика | Белые KPI и зелёный график; точные ₽, не маркетинговые проценты |
| 11. Финансы — операции | Добавить поступление/расход, категория, дата, сумма, история | Статус операции, возможность корректировки по серверным правилам |
| 12. Отчёты | Период, динамика, состав расходов, показатели записей | Отдельно фактические деньги и запланированные суммы услуг |
| 13. Материалы | Остатки, единицы г/мл/шт, критический порог, список | Мгновенно видно, что заканчивается, без декоративных картинок |
| 14. Движение материала | Приход, расход, причина, история движения | Любой остаток объясняется операциями, подтверждение списания |
| 15. Рабочий график | Рабочие дни, окна, перерывы, блокировки дат | Переключатели и время компактно; явная обратная связь о сохранении |
| 16. Настройки | Профиль, услуги, уведомления, интеграции, резервные копии | Строки навигации, состояние подключения, отсутствие ложных `Подключено` |

Если какой-либо экран или действие отсутствует в текущем backend, интерфейс должен показать неподключённое состояние или быть исключён из релиза; **не считать макет подтверждением наличия функции**. В частности, отчёты, статусы интеграций и связь финопераций с визитами требуют фактической проверки реализации.

## 8. UX-правила для мастера

1. **Главное действие за 1–2 касания.** В рабочий день первичны новая запись, перенос, завершение и поступление денег.
2. **Числа с сущностями.** `12 500 ₽` — что именно: цена услуги, ожидаемая выручка или фактическое поступление? Подпись обязательна.
3. **Не скрывать ограничения.** Пересечения времени, недоступные окна, отключённые Telegram/VK, отсутствие склада — текстом, а не только цветом.
4. **Показывать результат операции.** Сохранено / ожидает / не удалось + возможность безопасного повтора. Никакого «успешно» до ответа сервера.
5. **Суммы, единицы и даты.** Валюта ₽, единицы г/мл/шт, формат интерфейса `ДД.ММ.ГГГГ`; время 24 ч, timezone студии `Europe/Moscow` (Санкт-Петербург).
6. **Компактность.** Данные плотнее воздуха: 4–7 полезных строк на экран телефона, без раздутых пустых областей и огромных иконок.
7. **Отзывчивость.** Skeleton только при реальной загрузке; loading отключает повторный submit и предотвращает двойное создание операции.
8. **Реальные данные.** Синтетика в макетах должна быть помечена, не переносить красивые выдуманные суммы и персональные сведения в production.

## 9. Адаптивность и доступность

- Веб: контрольные ширины **320, 375, 425, 768, 1024, 1440 px**; мобильная запись — одна колонка, кнопка не обрезана.
- Android: **320×640**, **360×800**, **393×852**, **430×932**, плюс font scale **1.0 / 1.3 / 1.5**. Никакой обрезанной кнопки «Выход», перекрытых действий и горизонтального скролла форм.
- Все ключевые элементы доступны с TalkBack / keyboard (веб); иконки с понятными `contentDescription`.
- Состояния focus, pressed, disabled, error — реальные; цвет не единственный носитель информации.
- При плохом blur/performance отключить размытие; важнее кадры и читабельность, чем стеклянный эффект.
- Не применять непрозрачность к тексту целиком; проверять контраст после любого смешивания стеклянных слоёв.

## 10. Принятые принципы исходного DESIGN-nerdwallet.md и осознанные отклонения

| Исходное правило | Решение Stasy Bell |
|---|---|
| 8px базовая система и компактные интервалы | **Сохраняем** |
| Текстовая иерархия через размер + вес | **Сохраняем**, адаптируем к Android и editorial-заголовкам |

## 11. Правила реализации в репозитории

1. **Вынести семантические токены в единый источник для каждой платформы.** В `v2/web` — CSS variables / theme config; в `v2/android` — Compose `ColorScheme`, `Typography`, `Shapes`, `Spacing` и общие компоненты. Не размазывать HEX по отдельным экранам.
2. **Сохранить бизнес-логику и API.** Редизайн не должен менять правила бронирования, сохранения денег, подтверждения, прав доступа и учёта склада. UI рефакторить отдельно от контрактов.
3. **Сначала компонентная библиотека, затем экраны:** buttons → chips → inputs → rows → cards → navigation → calendar → finance → materials → settings. Иначе дизайн расползётся по десяти экранам.
4. **Сайт и Android — две разные реализации, один бренд.** Не переносить весь сайт в Android WebView. Не использовать сайтную светлую тему как случайный fallback приложения.
5. **Не заливать фон фотографиями в рабочем приложении.** В приложении 3D/листья только в допустимых фоновых декоративных областях. Для сайта фотографии — исключительно проверенные и разрешённые к публикации.
6. **Фиксировать визуальные снимки до и после** на одинаковых данных и размерах; проверять все 16 Android-экранов/состояний из перечня выше, а не только dashboard.
7. **Ветки:** дизайн и рефакторинг — от актуального `develop/stasy-bell-os-v2`; `main` не трогать и production не публиковать до отдельного согласования.

## 12. Критерии дизайн-приёмки (Definition of Done)

- [ ] Сайт соответствует теме **Sage Editorial Light**, Android — **Forest Glass Operational**. Отсутствуют старые фиолетовая, золотисто-бежeвая и случайные шаблонные палитры.
- [ ] Токены цветов централизованы; новые HEX не захардкожены по экранам.
- [ ] У всех основных компонентов единые размеры, отступы, радиусы, состояния и иконки.
- [ ] У сайта проверены главная, услуги, онлайн-запись, портфолио, контакты, статусы подтверждения.
- [ ] У Android проверены все рабочие экраны из раздела 7, включая пустые, загружающиеся и ошибочные состояния.
- [ ] Размеры, контраст, масштабирование и safe-area проверены на контрольных экранах.
- [ ] Нет визуального «шума»: навязчивого блеска, гигантских значков, лишних карточек и искусственных KPI.
- [ ] Скриншоты и Android UI-тесты сохранены; успешная сборка APK **не считается** визуальной приёмкой.
- [ ] Не изменилась бизнес-логика: записать, перенести, отменить, завершить, учесть деньги/материал.
- [ ] Реальные данные, согласия, доступы и интеграции не затронуты дизайном.

## 13. Краткая инструкция дизайнеру / Codex

**Задание:** реализовать Stasy Bell с двумя согласованными цветовыми темами и общим UX-языком по этому документу. Для сайта использовать светлый sage, editorial premium, крупную фотографию и ясную запись; для Android — глубокий зелёный hero, светлые рабочие поверхности, плотные данные, умеренное стекло и небольшие иконки. Не копировать чужой бренд NerdWallet. Не менять backend под требования макета. Начать с токенов и дизайн-компонентов, затем поочерёдно довести все экраны и прогнать визуальную + функциональную приёмку.

**Источники решения:** исходный `DESIGN-nerdwallet.md` — **структура и принципы**; утверждённые пользователем визуальные референсы — **палитры и характер**; этот файл — **нормативная спецификация для реализации**. При разногласиях между экспериментальным макетом и утверждённой спецификацией приоритет у этого файла до отдельной ревизии.
